Added orphaned `running` host-job reconciliation: the job runner now records its executor identity (pid, kernel boot id, start time) on the job record when a job enters `running`, and the new `omes job reconcile [--job <id>] [--json]` command proves a `running` job orphaned (host rebooted, runner pid gone or reused, or a pre-existing record with no runner identity older than `OMES_JOBS_ORPHAN_LEGACY_SECONDS`) and then reports only what the operation's existing read-back proves: `succeeded` (or `rolled_back` for a rollback) when a complete desired/observed pair matches, `failed` with `reconciliation_mismatch` when it does not, and `failed` with the new non-retryable `outcome_unknown` code (manual review required) whenever the outcome cannot be verified, never `succeeded` without read-back evidence; every reconciliation uses the existing `running` to terminal transitions (no new job state and no change to the `job-status.response` contract), appends a hash-chained `reconciled_orphan` audit entry, respects tenant/server scope and is idempotent, and the Hermes orchestration observer now treats an `UNKNOWN` subagent state as terminal non-success (counted in `failed_count`, never completed, never reverted to active by a late event, never turned into success by a later `SUCCEEDED`), while confirmed cancellation of a running job remains not implemented.
