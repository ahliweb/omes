Added two further opt-in flags to `omes health inference-endpoint`, `--probe-tool-call` and `--probe-stream`, valid only together with `--active-probe` (otherwise a usage error, exit 2; no environment variable can enable them). Each adds its own layer, `active_probe_tool_call` and `active_probe_stream`, present in the output only when requested, so existing output is unchanged. They run only after the plain active probe passed and reuse its vetted loopback or private address, pinned connection, no redirects, verified TLS, deadline, size cap and no-credential rules. The tool-call probe declares one fixed harmless tool that is never executed and passes only on a well-formed call of that tool; the streaming probe sends one fixed `stream: true` request and passes only on well-formed `data:` chunks that end with `[DONE]`, within a 256-event bound. Tool arguments, prompts and streamed text are never logged or printed. A pass is model-dependent and proves only that fixture; a text-only reply, wrong or malformed tool call, non-SSE, malformed, empty or unterminated stream, timeout or 401/403 is never ready. New reasons: `tool_call_missing`, `tool_call_wrong_name`, `tool_call_invalid`, `stream_not_sse`, `stream_malformed`, `stream_empty`, `stream_truncated`, `stream_too_long`. Credentialed endpoints and per-model fixtures remain Not implemented yet (tracked in #354).
