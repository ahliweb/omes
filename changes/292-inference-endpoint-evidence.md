Added `omes health inference-endpoint`, read-only and provider-neutral evidence for an already-configured local or private OpenAI-compatible inference endpoint that complements, and leaves unchanged, `omes health ollama` and Hermes provider readiness. It sends one metadata `GET /v1/models` (no prompt, no credentials), resolves the host once and refuses any public, link-local, cloud-metadata, multicast or otherwise non-private address before connecting to the vetted address with the original host name kept for `Host` and TLS verification, never follows redirects, always verifies TLS, caps the response size and total time, redacts credentials from the endpoint reference, and reports `pass`, `fail`, `not_applicable` or `unknown` per layer with `proves`, `source`, `authority` and `checked_at`, so a timeout, 401/403, redirect, malformed or oversized response, missing model, clock skew or absent configuration is never reported ready. The existing health layer model gained an additive `unknown` status that blocks readiness; the opt-in active synthetic probe is Not implemented yet (tracked in #292), and vLLM (#289) and Kubernetes (#290) remain deferred.
