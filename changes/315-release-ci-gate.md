scripts/release.sh now fails its CI gate closed. Because the GitHub Actions workflows are manual-only since #312, a release commit nobody dispatched them on has no check runs from them, and the old gate, which failed only on completed non-success check runs, passed with zero runs (or with only the automatic GitGuardian App check) and skipped itself silently when gh was not installed. A release now needs acceptable evidence for EVERY blocking job of lint.yml and compatibility.yml on the exact release commit from at least one of two sources: successful completed GitHub Actions check runs for each of those jobs (a missing, failed, cancelled or still-running required job, or a run from another app, is no evidence; advisory jobs are not required); additionally any completed check run on that commit with conclusion failure, timed_out or action_required, from any app and whether or not its job is required (for example a failing GitGuardian run), blocks the release in both paths and is named in the error, while a still-running non-required run only warns, or a local evidence file produced by scripts/ci-local.sh --profile full --json (default .omes-ci/ci-local-<sha>.json, or --ci-evidence PATH) that is strictly validated by the new scripts/release-ci-gate.py: valid JSON for exactly that commit SHA, clean tree, non-shallow clone, result pass, every blocking job including the matrix and real-install jobs passed, and a generated_at timestamp that is not in the future; this evidence is self-reported, bound to the commit SHA and not enforced by GitHub. Without evidence the release exits 1 naming the missing jobs and both remedies (gh workflow run lint.yml and compatibility.yml, or the local run), a missing gh no longer skips the gate, and the required job names come from scripts/ci-local.sh --list --json (which now also reports each job's check_name and a generated_at timestamp). The explicit --skip-ci-check opt-out remains, is never the default, prints a prominent warning and is recorded in the annotated tag message and the GitHub Release notes; --dry-run stays network-free and non-mutating and only reports what the gate would require (docs/ci.md section 8.1, docs/business/release-gates.md).
