Extended the read-only `omes agent isolation-drift` declared-versus-running check for the rootless Compose backend to compare more running-container hardening fields from `docker inspect`: any `HostConfig.CapAdd` (critical for `ALL` or `SYS_ADMIN`, otherwise high), any `Devices` mapping, a seccomp or AppArmor override (`unconfined` is high, a custom profile is medium and its body is never printed) or any other undeclared `SecurityOpt` entry, and a non-private `IpcMode` (critical for `host`, high for `container:<id>`, low otherwise). The renderer declares none of these, so Docker's default is the expectation and only an undeclared override is drift; the default seccomp and AppArmor profiles cannot be proven active from `docker inspect` and are listed under `skipped` as not declared. A field that is missing from the inspect output or has an unexpected type (now including `CapDrop`, `SecurityOpt`, `Privileged`, `NetworkMode` and `PidMode`, which were previously assumed safe when absent) is reported under `unverified` and yields `unknown`, never `ok`. The check is still two fixed read-only `docker inspect` / `docker network inspect` commands. `docs/agent-deployment.md` gains an isolation profile matrix (control versus enforcing authority versus verified-by), and a per-destination egress allowlist, a runtime egress probe, real rootless-daemon evidence, orphan cleanup and retention, and `omes agent doctor` or schedule wiring remain not implemented yet (tracked in #276).
