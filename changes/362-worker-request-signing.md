The pull worker now generates a real Ed25519 key locally with OpenSSL 3 (fixed argv, timeout, no shell, no new Python dependency) instead of a fabricated one, keeps the private key in its own mode `0600` file under `$OMES_STATE_DIR/worker/` (never in `credentials.json` or a backup), proves possession by signing the enrollment challenge, and signs every poll, result and heartbeat request with `OMES-WORKER-SIG-V1` over method, path, body digest, nonce and timestamp (`X-OMES-Worker-Id`, `X-OMES-Timestamp`, `X-OMES-Nonce`, `X-OMES-Signature`). Enrollment fails closed without an Ed25519-capable OpenSSL, and credentials stored by the old fake scheme are refused with a re-enrollment message instead of being migrated. `worker-enrollment.request` now requires a raw base64 `public_key`, `public_key_algorithm: "ed25519"` and `challenge_signature` (AWCMS must re-vendor it, see `contracts/README.md`), and the compatibility manifest reports `worker_protocol.request_signing: "ed25519-v1"`. ADR-0027, `docs/jobs.md`, `docs/security.md` and the threat model (CC22, CC23) state what is implemented. Not implemented yet (tracked in #362): Control Center verification of the enrollment proof, signatures, nonce replay and clock skew, and key rotation or revocation.
