# Changelog

All notable changes to OMES are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and OMES uses
[Semantic Versioning](https://semver.org/). Entries are compiled from
`changes/*.md` fragments by `scripts/release.sh` (see
`docs/adr/0010-versioning-and-change-fragments.md`); do not edit by hand.

## [0.7.0](https://github.com/ahliweb/omes/releases/tag/v0.7.0) - 2026-10-24

### Security

- Fixed the automated upstream-drift report's Hermes finding always showing "Current Baseline: n/a" (a lexicographic-sort bug that let a logical-boundary capability's `n/a` placeholder outrank a real pinned version), raised the verified-and-pinned Hermes Agent installer baseline to v2026.9.24 (v0.21.5, verified installer SHA-256 recorded in `lib/omes/versions.sh` after reviewing the downloaded installer for new remote fetches, sudo, or unverified execution), raised the Graphify baseline to 0.9.71 after re-verifying extraction, export, hook, and Hermes skill-install behavior against a live install, and raised the documented-but-not-live-tested Coolify adapter baseline to v4.3.23 after confirming via the upstream changelog that none of its `POST`/`GET` breaking changes or the `host_path` removal affect the read/deploy/rollback endpoints OMES's Coolify client actually calls. ([#259](https://github.com/ahliweb/omes/issues/259))
- `omes job submit` now enforces the documented default-deny tenant scope: when `OMES_JOBS_TENANT_ID` is unset (or empty) every submission is refused with the new `tenant_not_configured` error (`TenantNotConfiguredError`, a `CrossTenantError` subclass) before any job record, idempotency entry, or audit line is written; previously an unconfigured host accepted any `tenant_id`. Upgrade note: hosts that ran `omes job submit` without `OMES_JOBS_TENANT_ID` must now set it to their enrolled tenant. The pull worker is unaffected because it uses the tenant it was enrolled under (`omes worker enroll --tenant`). `OMES_JOBS_SERVER_ID` remains optional, and `docs/configuration.md`, `docs/jobs.md`, and `docs/security.md` no longer claim the rejection is audited. ([#279](https://github.com/ahliweb/omes/issues/279))
- scripts/release.sh now fails its CI gate closed. Because the GitHub Actions workflows are manual-only since #312, a release commit nobody dispatched them on has no check runs from them, and the old gate, which failed only on completed non-success check runs, passed with zero runs (or with only the automatic GitGuardian App check) and skipped itself silently when gh was not installed. A release now needs acceptable evidence for EVERY blocking job of lint.yml and compatibility.yml on the exact release commit from at least one of two sources: successful completed GitHub Actions check runs for each of those jobs (a missing, failed, cancelled or still-running required job, or a run from another app, is no evidence; advisory jobs are not required); additionally any completed check run on that commit with conclusion failure, timed_out or action_required, from any app and whether or not its job is required (for example a failing GitGuardian run), blocks the release in both paths and is named in the error, while a still-running non-required run only warns, or a local evidence file produced by scripts/ci-local.sh --profile full --json (default .omes-ci/ci-local-<sha>.json, or --ci-evidence PATH) that is strictly validated by the new scripts/release-ci-gate.py: valid JSON for exactly that commit SHA, clean tree, non-shallow clone, result pass, every blocking job including the matrix and real-install jobs passed, and a generated_at timestamp that is not in the future; this evidence is self-reported, bound to the commit SHA and not enforced by GitHub. Without evidence the release exits 1 naming the missing jobs and both remedies (gh workflow run lint.yml and compatibility.yml, or the local run), a missing gh no longer skips the gate, and the required job names come from scripts/ci-local.sh --list --json (which now also reports each job's check_name and a generated_at timestamp). The explicit --skip-ci-check opt-out remains, is never the default, prints a prominent warning and is recorded in the annotated tag message and the GitHub Release notes; --dry-run stays network-free and non-mutating and only reports what the gate would require (docs/ci.md section 8.1, docs/business/release-gates.md). ([#315](https://github.com/ahliweb/omes/issues/315))
- `omes job reconcile` is now default-deny on tenant scope, matching `omes job submit` (#279): when no local tenant is configured (`OMES_JOBS_TENANT_ID` unset or empty) both the batch run and `--job <id>` refuse with `tenant_not_configured` (`TenantNotConfiguredError`, exit 1, `{"error": "tenant_not_configured", ...}` under `--json`) before any job is loaded, read back, transitioned, saved or audited, where previously an unset variable made a batch run reconcile every running job of every tenant; jobs whose tenant does not match the configured tenant are still skipped (batch) or refused as `cross_tenant_rejected` (`--job`), tenant resolution now goes through the single `store.resolve_local_tenant()` shared with `store.submit()`, and `docs/jobs.md` documents the `enrolled_tenant_id` over `OMES_JOBS_TENANT_ID` precedence. ([#318](https://github.com/ahliweb/omes/issues/318))

Reconciliation re-reads the job record from disk before assessing it and again right before writing, and leaves the job `unchanged` (reason `no_longer_running`, no audit entry) if it is no longer `running` or its runner identity changed, so a terminal state saved by the real runner is not overwritten (a re-check, not a lock). ### Changed

- Extended the read-only `omes agent isolation-drift` declared-versus-running check for the rootless Compose backend to compare more running-container hardening fields from `docker inspect`: any `HostConfig.CapAdd` (critical for `ALL` or `SYS_ADMIN`, otherwise high), any `Devices` mapping, a seccomp or AppArmor override (`unconfined` is high, a custom profile is medium and its body is never printed) or any other undeclared `SecurityOpt` entry, and a non-private `IpcMode` (critical for `host`, high for `container:<id>`, low otherwise). The renderer declares none of these, so Docker's default is the expectation and only an undeclared override is drift; the default seccomp and AppArmor profiles cannot be proven active from `docker inspect` and are listed under `skipped` as not declared. A field that is missing from the inspect output or has an unexpected type (now including `CapDrop`, `SecurityOpt`, `Privileged`, `NetworkMode` and `PidMode`, which were previously assumed safe when absent) is reported under `unverified` and yields `unknown`, never `ok`. The check is still two fixed read-only `docker inspect` / `docker network inspect` commands. `docs/agent-deployment.md` gains an isolation profile matrix (control versus enforcing authority versus verified-by), and a per-destination egress allowlist, a runtime egress probe, real rootless-daemon evidence, orphan cleanup and retention, and `omes agent doctor` or schedule wiring remain not implemented yet (tracked in #276). ## [0.5.0](https://github.com/ahliweb/omes/releases/tag/v0.5.0) - 2026-09-27

### Security

- Add opt-in retention and rotation for AI-privacy posture evidence OMES itself persists: `omes health ai-privacy` remains a point-in-time report that persists nothing by default, `--persist` re-validates the bounded evidence object against the published posture-evidence schema (which also runs the existing secret-value/secret-field scan) and refuses to write anything that fails, writing only a validated record to the OMES-owned `<state-dir>/ai-privacy-evidence/` directory (mode 0700/0600), and the new `omes health ai-privacy prune [--max-age-days] [--max-count] [--dry-run] [--json]` command deletes expired or excess records confined strictly to that directory, refusing symlinks and any file not matching its own naming pattern, idempotently and with dry-run support; both operations additionally `os.lstat` the evidence directory itself (never following a symlink) and refuse a symlinked, foreign-owned, or group-/world-writable directory outright, and a record's retention age is the older of its filesystem mtime age and its recorded timestamp so a tampered far-future timestamp can never suppress pruning. ([#234](https://github.com/ahliweb/omes/issues/234))
